# M2 — Reader/storage architectural proof

**Result:** standalone reader/storage boundaries work on actual desktop Chromium for the named bounded contracts. This is not production migration, complete EPUB security, server deduplication, or installed-PWA qualification. Implementation and instructions: [`prototypes/reader-storage`](../../prototypes/reader-storage/README.md).

Authority: [migration design](../frontend-migration.md), [approved M2 defaults](README.md#product-decisions-for-m2), [reader/offline evaluation](reader-offline.md), [architecture/tooling evaluation](architecture-tooling.md), and the M2 reader/storage request. Approved logout retention and original forward-turn/WPM measurement supersede alternatives in the older M1 reader report. No root app/dependency/API files, server data, or private snapshot were touched. No git operations were used.

## Architecture and contracts

### Current production state (read-only evidence)

- `assets/reader/index.js` combines EPUB.js, application DOM, KO conversion, activity measurement, IndexedDB writes, and HTTP; no controller disposal exists. Its script-enabled configuration is **not** retained.
- `assets/local/index.js`, `assets/index.js`, `assets/common.js`, and `assets/sw.js` distribute book/queue/cache ownership; broad deletion and non-account-scoped records are retired assumptions, not proof contracts.
- `utils/utils.go` defines complete-1024-byte-sample partial MD5; `utils/utils_test.go` fixes Alice's partial/full hash vectors. Server identity and `/body/DocFragment[n]/body/...` progress remain external contracts.

### Precision and lifecycle findings

A page can start halfway through a paragraph. Restoring that paragraph's KO path can legitimately show the preceding page. The proof retains the **logical saved KO anchor**, verifies that element intersects the rendered viewport after restore/reflow, and does not replace it with the restored page's first visible word. This is element-level compatibility, not character/page-exact precision. The original report's statement that descendant-only reads mirrored the existing boundary was incorrect: production has contradictory writer/reader algorithms. The exact selected semantics and remaining ambiguity are described below; a real KOReader client has not been exercised.

**Chosen KO semantics, based on the actual legacy read/write code:** `assets/reader/index.js:1017–1087` writes descendant tag indices and skips anchor parents. In contrast, `1094–1202` reads a namespaced **child-axis XPath first** (`1163–1170`), then selects the first XPath result **or** the descendant-selector fallback (`1193`). They are not inverse algorithms. The proof accepts the existing DocFragment grammar, removes the supported `.digits`/text suffix for element lookup, evaluates the full child-axis path, and uses the full descendant reduction only if XPath returns no element. Input strings remain opaque saved values; lookup normalization does not persist a replacement.

For `<div><blockquote><p id="nested"/></blockquote><p id="first"/><p id="second"/></div>`, existing `…/div[1]/p[2]` therefore reads **second**, as the production reader does, not **first** as the legacy writer intended. `…/div[1]/p[3]` has no child-axis result and falls back to **second**. The real-engine `nested.epub` repeats these cases with both blockquote and figure wrappers and retains the exact saved `p[2]` string. New writing still constructs the legacy descendant-index/anchor-omission format, but verifies that reading its result selects the original element: attempting to write **first** fails recoverably rather than publishing a path that would reopen **second**. Missing/unsupported locations remain errors, never automatically published fallbacks. Omitted-anchor image `.0`, bare body, repeated tags and namespace fixtures remain active. This neither repairs contradictory historical paths nor proves what a real KOReader client intended; that cross-client qualification remains pending.

Actual browser listener instrumentation exposed two EPUB.js leaks: an anonymous `window.unload` callback and `orientationchange` registered but `orientationChange` removed. The small pinned manager seam contains these. It is an upstream maintenance dependency, not permission to scatter engine internals through React. Real global-listener/object-URL counts return to their pre-reader baseline across three mounts. No application wake lock, polling loop, or app-created EPUB URL exists in this proof. Resource destruction can wait for an in-flight engine operation; a permanently hung parse/render has no force-cancellation watchdog and remains a limitation.

## Explicit limits / not solved

1. **Content isolation is conditional.** Ideal is a separate/opaque origin with no app credentials and a small bridge. Pragmatic proof is same-origin parent DOM access with book scripts disabled, conservative preflight rejection and early CSP. It rejects benign EPUB features too (SVG/audio/video/forms, external links, CSS functions/at-rules/escapes, URL-bearing CSS/fonts and unknown resource types); no broad EPUB compatibility claim. Internal links are intentionally blocked in this harness; production must route validated internal links through the controller, not silently remove that capability. No unsafe scripted fallback is retained.
2. **Archive resource exhaustion is not solved.** Compressed/entry/expanded budgets exist (8 MiB/256/24 MiB), but JSZip allocates an entry before checking expanded totals, and duplicate-name/forged-size/ZIP-bomb/CRC/cancellation/large-media hardening is incomplete. Structure validation is a conservative subset, not a complete EPUB validator. Original bytes remain unchanged; equal-size byte corruption/book revision and content-version conflict are not fully detected by the repository size check.
3. **EPUB.js diagnostics remain.** Chromium logs CFI `setting end offset ... failed` diagnostics and iframe `ResizeObserver loop completed with undelivered notifications`, especially during test-only hostile-frame replacement and teardown. They are not suppressed or presented as a clean console result. Assertions still pass; the engine's range/resize behavior needs production investigation. Global listeners/URLs are measured, not a heap/GC proof or every iframe media-query/timer path.
4. **Server correctness is not manufactured in the browser.** The fake has process-local receipts/head, not durable server transactions, a real HTTP parser, cookie/CSRF/auth negotiation, or KO participation. Required production receipts must commit with effects; every web/KO progress writer must advance the same revision; receipt lookup precedes conflict checks on retries. Fake state and the visible conflict dialog do not survive server/page restart; durable checkpoint/outbox do. Local event/receipt types now compose with the API proof's generated `components` through type-only imports; the browser runtime needs neither the API client package nor API node_modules. `wire.ts` follows the reviewed request revision grammar in `openapi.yaml` and `isProgressAcknowledgement` semantics in `client/client.ts`, and additionally checks exact fields, kind, ID, activity-null revision and progress receipt revision equal to base+1. Request/head revisions start at `"0"`; committed progress receipts are positive strings. BigInt is used only for exact increment/check arithmetic, never percentage/clock ordering. The runtime predicate is locally implemented, not imported from the API client; sharing/future runtime-predicate drift qualification remains part of HTTP integration. The fake/coordinator tests integrate CAS with durable events, not just a separate dialog. **Actual HTTP integration is still pending**: no cookies/CSRF/media-type/response parsing/generated-client network call, durable server ledger, comprehensive payload canonicalization, KO writer participation, retry/backoff UI or durable conflict-resolution flow is claimed. `device_id` is explicit installation-specific fixture identity, not an invented schema field. API proof endpoints accept individual events; fake replay models those per-event effects (a later conflict can leave earlier receipts committed for safe retry), not an atomic batch endpoint. No API-agent files/dependencies were changed.
5. **Activity integration is intentionally incomplete.** The approved formula is isolated and tested; this page emits checkpoints, not real credited activity. Accurate visible-word extraction across real EPUBs and end-to-end production measurement→event capture still need qualification. No idle/background/close policy has been added under the guise of durability.
6. **Browser durability has a narrow meaning here.** Page reload + IndexedDB close/reopen, transaction fault injection, two tabs and offline engine open are tested. No full OS/browser termination, physical storage pressure/eviction/private mode, real quota, crash during native commit, installed launch, persisted-storage guarantee, backup/export flow or real-device iOS/Android test was performed. Account scoping is application-level separation, not encryption or protection from someone inspecting the same browser profile. Session/access state is a persisted synthetic model, not authentication credentials.
7. **SW retirement/update proof is deferred.** No fresh worker registration is offered as a production-PWA result. A disposable root-origin retirement harness would not establish actual deployment/cached-client cutover, and broadening this proof would dilute the named reader/storage contracts. Recommended strategy remains replacement at existing `/sw.js`, one-time known-legacy cache/IDB/localStorage cleanup, controlled legacy-client reload, unrelated/new-schema preservation, then future updates deferred during active reading with app/schema/API compatibility checks. Test old-controller reconnection, multiple/waiting clients, blocked IDB deletion, failed precache and retained new outbox before production. A loaded shell can reopen stored books offline here; a cold offline shell launch is **not** implemented.
8. **Platform/parity gates remain.** No Safari/iOS (physical or Playwright WebKit), Android installed PWA, real KOReader, RTL/spreads/fixed layout, accessibility audit, large-book performance, gestures/theme/device/wake-lock parity, or production Go asset/deep-link/CSP deployment proof. Desktop Chromium alone cannot close these gates.

## Recommendation and handoff

**Ideal:** promote only after broader EPUB isolation/compatibility, shared durable server receipts/revisions including KO writes, worker cutover, and physical-device qualification. **Pragmatic:** retain this discardable pinned harness as acceptance evidence, integrate its boundary contracts with the parent API proof, and resolve the listed limits before an end-to-end slice. Do not promote this page or its fake into a parallel production architecture.

Knowledge capture: if this seam is promoted, add a reader-package `AGENTS.md` documenting partial-MD5 versus full integrity hash, KO-path versus CFI precision, the contradictory child-axis reader/descendant writer and recoverable disagreement rule, the pinned engine cleanup deviations, and lease-epoch/receipt-before-conflict ordering. Keep platform/SW qualification in dedicated deployment tests/docs, not global guidance.

### Task-end report

- **Assumptions made:** callers supply canonical server origin and immutable account/server document IDs; synthetic access state models the approved logout/expiry policy, not real authentication.
- **Decisions made autonomously:** strict role/structure rejection rather than sanitization; production child-axis reader precedence plus recoverable writer disagreement; single-use controller; isolated disposable proof DB v2 (v1 untouched); generated type-only API coupling with local stricter receipt gate and deterministic CAS transport; no SW or HTTP server integration.
- **Compromises:** narrower EPUB/desktop-only evidence, no production activity/HTTP/KO/PWA integration, and no hard decompression cancellation. These keep the work bounded and avoid claiming guarantees the browser-only proof cannot provide.
