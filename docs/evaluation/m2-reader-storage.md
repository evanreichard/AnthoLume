## Architecture and contracts

### Current production state (read-only evidence)

- `assets/reader/index.js` combines EPUB.js, application DOM, KO conversion, activity measurement, IndexedDB writes, and HTTP; no controller disposal exists. Its script-enabled configuration is **not** retained.
- `assets/local/index.js`, `assets/index.js`, `assets/common.js`, and `assets/sw.js` distribute book/queue/cache ownership; broad deletion and non-account-scoped records are retired assumptions, not proof contracts.

### Selected content policy (one bounded compatibility proof)

The user selected the single-origin target after reading `_scratch/m2/review-isolation/decision.md` and [the isolation feasibility report](m2-reader-isolation.md). That report falsified an opaque-outer/nested-frame topology; it is not a requirement for a new hostname here. This task changes only this reader/storage prototype/report, not isolation, API, design or integration artifacts.

- **Execution boundary:** trusted controller in the app origin; every EPUB.js chapter is `sandbox="allow-same-origin"` without `allow-scripts` or popups. Validation uses inert XML and template documents; **live chapter parsing** receives a complete serialized head with the strict CSP first, before any book head. `script-src`, `connect-src`, frames, objects, forms and base URI are none; image/style/font assets are owned blobs (inline style is allowed). There is no scripted-content fallback.
- **CSS is parsed, not declared unsafe wholesale.** CSS Tree parses ASTs with recovery/Raw rejection, validates supported declarations/descriptors, and visits decoded URL nodes. The bounded subset includes rgb/rgba/hsl colors, calc/min/max/clamp, selected gradients/transforms, `@media`, UTF-8 `@charset`, and packaged-font `@font-face` with `format()`. `@import`, custom properties/var indirection, local system-font discovery, image-set string sources and unsupported functions/at-rules remain explicit rejections. Escaped URL values are decoded before URI checks; an escaped `url` function that the parser represents as a generic function is rejected, not passed through. This is not a claim that every excluded CSS feature is dangerous.
- **Resource confinement:** all CSS, HTML and SVG fetching references resolve against the effective archive entry, must match validated manifested roles, and materialize only as controller-owned blob URLs. Relative parent directories **within** the archive are supported; schemes, absolute/root-relative URLs, queries, encoded separators, double encodings and archive escape reject. Book-authored data/blob URLs reject. Image/font signatures complement MIME/extension consistency; SVG is parsed structurally with passive shapes/text/defs/gradients/local use/image and local paint references. Scripts, event attributes (including metadata), foreignObject, animation, external SVG references and unsupported resource hints reject regardless of a misleading filename/MIME. CSS and packaged SVG URLs are canonicalized recursively; cycles are unsupported.
- **Body/identity preservation:** original EPUB bytes are stored/opened unchanged. Render-time asset attributes/CSS references change; body hierarchy, text, tag namespaces and IDs do not. No nodes are removed/rearranged as sanitization. The trusted loader clones validated XML according to its declared XHTML role, because EPUB.js otherwise chooses HTML parsing for `.html` regardless of OPF MIME. HTML serialization emits closing tags for empty nonvoid XHTML elements. An inert template-owned HTML root round-trips the whole document, comparing both head and body hierarchies/text/namespaces/IDs. It rejects head text that would manufacture body markup as well as ordinary HTML tree repair. Only ASCII formatting whitespace outside head/body is omitted from render serialization, so trailing XML indentation cannot become extra book body text; source head/body and stored bytes are unchanged. Stock regex substitution of serialized chapter text is disabled, so literal body text such as `drawing.svg font.woff2 style.css` remains text. Alice's original `<div class="figcenter c1"/>` was independently observed swallowing later content under the stock loader; the corrected loader/serializer and actual rendered-body comparisons catch this.
- **Navigation:** preflight validates internal chapter/fragment targets against the original spine and IDs, including NCX navPoint destinations. Controller TOC commands map raw hrefs to canonical targets using the effective selected NAV/NCX document base (`book.packaging.navPath || ncxPath`), never the OPF base. The map is controller-local; original OPF/navigation/body hrefs and public TOC href values are not rewritten. Click/keyboard-generated click and auxiliary-click capture prevent native frame navigation; supported clicks are serialized with TOC/page commands. Fragment navigation obtains a codec anchor, so one intentional navigation publishes one location. Restore/reflow/font loading never auto-publish. Non-spine files, missing fragments and post-validation injected API links fail without a fallback checkpoint. External links remain rejected, not silently opened. Context-menu/platform interaction beyond these tested events remains unqualified.
- **Precise passivity evidence:** normal books and all rejected fixtures produce zero forbidden request attempts. The positive HTTP allowlist is parent-main-frame GET-only; all chapter HTTP(S) is forbidden even for same-origin fixture URLs. One test-only exception permits exactly `/fixtures/passive-navigation-target.html` for privileged automation self-navigation of the existing frame. That target intentionally has no CSP and a script attempting parent DOM/storage mutation: both stay unchanged with no-scripts, but both change under the deliberate `allow-scripts` fault. This proves sandbox lifetime, not exclusion from the application origin or real production cookie behavior. Arbitrary outbound probes are recorded **and aborted**; no attacker/API endpoint is contacted.

The original benign representative is copied byte-for-byte from the sibling's public synthetic `benign.epub` into this proof; sibling source/files are not edited. An additional own-directory fixture extends it with parent-relative assets, local SVG use/gradient and same-document links. Alice remains solely the checked-in public `_test_files/alice.epub`. All generated packages are deterministic. Ordinary compatibility is proven for these named fixtures, not every EPUB; unsupported markup, audio/video/forms, resource roles, font formats and non-round-trippable bodies still fail explicitly.

### Precision and lifecycle findings

A page can start halfway through a paragraph. Restoring that paragraph's KO path can legitimately show the preceding page. The proof retains the **logical saved KO anchor**, verifies that element intersects the rendered viewport after restore/reflow, and does not replace it with the restored page's first visible word. This is element-level compatibility, not character/page-exact precision. The original report's statement that descendant-only reads mirrored the existing boundary was incorrect: production has contradictory writer/reader algorithms. The exact selected semantics and remaining ambiguity are described below; a real KOReader client has not been exercised.

**Chosen KO semantics, based on the actual legacy read/write code:** `assets/reader/index.js:1017–1087` writes descendant tag indices and skips anchor parents. In contrast, `1094–1202` reads a namespaced **child-axis XPath first** (`1163–1170`), then selects the first XPath result **or** the descendant-selector fallback (`1193`). They are not inverse algorithms. The proof accepts the existing DocFragment grammar, removes the supported `.digits`/text suffix for element lookup, evaluates the full child-axis path, and uses the full descendant reduction only if XPath returns no element. Input strings remain opaque saved values; lookup normalization does not persist a replacement.

For `<div><blockquote><p id="nested"/></blockquote><p id="first"/><p id="second"/></div>`, existing `…/div[1]/p[2]` therefore reads **second**, as the production reader does, not **first** as the legacy writer intended. `…/div[1]/p[3]` has no child-axis result and falls back to **second**. The real-engine `nested.epub` repeats these cases with both blockquote and figure wrappers and retains the exact saved `p[2]` string. New writing still constructs the legacy descendant-index/anchor-omission format, but verifies that reading its result selects the original element: attempting to write **first** fails recoverably rather than publishing a path that would reopen **second**. Missing/unsupported locations remain errors, never automatically published fallbacks. Omitted-anchor image `.0`, bare body, repeated tags and namespace fixtures remain active. This neither repairs contradictory historical paths nor proves what a real KOReader client intended; that cross-client qualification remains pending.

Actual browser listener instrumentation exposed two EPUB.js leaks: an anonymous `window.unload` callback and `orientationchange` registered but `orientationChange` removed. The small pinned manager seam contains these. It is an upstream maintenance dependency, not permission to scatter engine internals through React. Real global-listener/object-URL counts return to their pre-reader baseline across three mounts. No application wake lock, polling loop, or app-created EPUB URL exists in this proof. Resource destruction can wait for an in-flight engine operation; a permanently hung parse/render has no force-cancellation watchdog and remains a limitation.

## Explicit limits / not solved

1. **Single-origin risk is explicitly user-accepted.** Trusted EPUB.js/JSZip/CSS Tree/controller code runs with app-origin privileges. Chapter sandbox no-scripts, early CSP, archive confinement and link routing do not confine a trusted-engine/native-decoder vulnerability away from app credentials. This is the selected target, not an unsafe fallback or permanent-origin-exclusion claim. The forced-navigation probe is privileged automation, not a book capability: a scriptless same-origin GET can still render a spoofed page if trusted code navigates there. Real server no-GET-side-effects/cookie/deployment review remains integration work. No claim of complete EPUB sanitization or all-EPUB compatibility follows.
2. **Archive resource exhaustion is not solved.** Compressed/entry/expanded budgets exist (8 MiB/256/24 MiB), but JSZip allocates an entry before checking expanded totals, and duplicate-name/forged-size/ZIP-bomb/CRC/cancellation/large-media hardening is incomplete. Structure/resource validation, binary magic and inert body round-trip checks are a supported subset, not complete EPUB/font/image conformance or a decoder security audit. CSS complexity, resource decode time and parser cancellation are also unqualified. Original bytes remain unchanged; equal-size byte corruption/book revision and content-version conflict are not fully detected by the repository size check.
3. **EPUB.js diagnostics remain.** Chromium logs CFI `setting end offset ... failed` diagnostics and iframe `ResizeObserver loop completed with undelivered notifications`, especially during test-only hostile-frame replacement and teardown. They are not suppressed or presented as a clean console result. Assertions still pass; the engine's range/resize behavior needs production investigation. Global listeners/URLs are measured, not a heap/GC proof or every iframe media-query/timer path.
4. **Server correctness is not manufactured in the browser.** The fake has process-local receipts/head, not durable server transactions, a real HTTP parser, cookie/CSRF/auth negotiation, or KO participation. Required production receipts must commit with effects; every web/KO progress writer must advance the same revision; receipt lookup precedes conflict checks on retries. Fake state and the visible conflict dialog do not survive server/page restart; durable checkpoint/outbox do. Local event/receipt types now compose with the API proof's generated `components` through type-only imports; the browser runtime needs neither the API client package nor API node_modules. `wire.ts` follows the reviewed request revision grammar in `openapi.yaml` and `isProgressAcknowledgement` semantics in `client/client.ts`, and additionally checks exact fields, kind, ID, activity-null revision and progress receipt revision equal to base+1. Request/head revisions start at `"0"`; committed progress receipts are positive strings. BigInt is used only for exact increment/check arithmetic, never percentage/clock ordering. The runtime predicate is locally implemented, not imported from the API client; sharing/future runtime-predicate drift qualification remains part of HTTP integration. The fake/coordinator tests integrate CAS with durable events, not just a separate dialog. **Production HTTP integration remains pending.** The separate [accepted HTTP proof](m2-integration.md#independent-acceptance) composes this Repository/SyncCoordinator/receipt gate with actual Go HTTP, signed fixture cookies/CSRF, SQLite receipts and explicit fixture conflict resolution; this reader page still uses a fake. Production authentication/KO writer participation, full response validation/canonicalization, retry/backoff UI and durable conflict-resolution ownership/history remain later work. `device_id` is explicit installation-specific fixture identity, not an invented schema field. API proof endpoints accept individual events; fake replay models those per-event effects (a later conflict can leave earlier receipts committed for safe retry), not an atomic batch endpoint. No API-agent files/dependencies were changed.
5. **Activity integration is intentionally incomplete.** The approved formula is isolated and tested; this page emits checkpoints, not real credited activity. Accurate visible-word extraction across real EPUBs and end-to-end production measurement→event capture still need qualification. No idle/background/close policy has been added under the guise of durability.
6. **Browser durability has a narrow meaning here.** Page reload + IndexedDB close/reopen, transaction fault injection, two tabs and offline engine open are tested. No full OS/browser termination, physical storage pressure/eviction/private mode, real quota, crash during native commit, installed launch, persisted-storage guarantee, backup/export flow or real-device iOS/Android test was performed. Account scoping is application-level separation, not encryption or protection from someone inspecting the same browser profile. Session/access state is a persisted synthetic model, not authentication credentials.
7. **SW runtime retirement/update proof is deferred.** The [M2 retirement/reset contract](service-worker-contract.md) is defined; its acceptance matrix remains unexecuted M3/M5 work. No fresh worker registration is offered as a production-PWA result. A disposable root-origin retirement harness would not establish actual deployment/cached-client cutover, and broadening this proof would dilute the named reader/storage contracts. Recommended strategy remains replacement at existing `/sw.js`, one-time known-legacy cache/IDB/localStorage cleanup, controlled legacy-client reload, unrelated/new-schema preservation, then future updates deferred during active reading with app/schema/API compatibility checks. Test old-controller reconnection, multiple/waiting clients, blocked IDB deletion, failed precache and retained new outbox before production. A loaded shell can reopen stored books offline here; a cold offline shell launch is **not** implemented.
8. **Platform/parity gates remain.** No Safari/iOS (physical or Playwright WebKit), Android installed PWA, real KOReader, RTL/spreads/fixed layout, accessibility audit, large-book performance, gestures/theme/device/wake-lock parity, or production Go asset/deep-link/CSP deployment proof. Source-tree-preserving XML loading avoids the stock `.html` repair, but cannot establish historical paths created against a previously repaired tree or real KOReader intent; existing server strings are never rewritten. Desktop Chromium alone cannot close these gates.

**Ideal:** integrate this selected single-origin boundary only with shared durable server receipts/revisions including KO writes, M3 archive hardening, worker cutover and physical-device qualification. **Pragmatic:** retain the bounded compatibility/security harness as executable evidence and proceed to the same end-to-end integration gates. No additional topology round or dedicated hostname is proposed. Do not promote this page or its fake into a parallel production architecture.
