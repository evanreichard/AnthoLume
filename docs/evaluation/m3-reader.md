## Target state and delivered boundaries

Original source is disk-backed: local File/Blob range reads, or a download streamed into **256 KiB IndexedDB chunks**. No import/open/hash/parser/renderer whole-book ArrayBuffer/concat/copy exists on the production path. Source SHA-256 is incremental in a terminable worker (`@noble/hashes@2.0.1`, pinned by frontend); KO partial MD5 uses upstream sample offsets and includes short reads at the end of the original. It is separate from full integrity and server identity; neither digest rewrites existing server IDs or historical position/activity data.

A bounded range index validates every raw central/local ZIP record before any inflate: names/UTF-8/NFC/duplicates/escape/ZIP64/extras/flags/methods/descriptors/contiguous ranges/overlap and declared limits. Resource requests then stream DEFLATE/STORE through actual-output/CRC/SHA checks. Complete validation traverses resources sequentially; it retains compact roles/IDs/word counts/dependency metadata, **not expanded bytes or all chapter DOMs**. Publication atomically commits source completeness, index/integrity metadata, book metadata and checkpoint/head; quota/abort/crash stages are never available.

Open verifies bounded manifest metadata and uses saved chunk/entry digests on demand, **not a fresh whole-original hash/inflate pass**. The actual EPUB.js controller loads validated documents through OPF. Canonical DOM LRU is two documents; inactive engine sections/listeners and asset leases release. Fonts/CSS/static SVG dependencies are bounded; raster IMG bytes/URLs/decoded images load for the actual visible viewport, with original intrinsic dimensions reserved before decode and no prefetch. A ready page waits for its real images, never fake omissions. Offscreen raster sources/leases are released. Whole-book decoded-pixel totals are retired in favor of resource/visible-page budgets independent of book size.

Download memory required a real correction: merely writing serial main-world chunks still produced ~300 MB of unforced backing storage. Incoming BYOB buffers now **transfer ownership** to a staging worker. It commits bounded source chunks and rotates/terminates after each **8 MiB window**, rather than relying on main-world GC. The root SW still owns only shell/control state; staging workers own only original source bytes, never books/events/auth/replay.

State owners: `repository.ts` owns source publication and durable reading decisions; `staging-writer.ts`/`staging.worker.ts` own transferred write windows; `source.ts`/`source.worker.ts` own range scheduling/index/hash/inflate; `content-policy.ts`/`book-manifest.ts` own validation evidence; `chapter-policy.ts` owns DOM/image/URL working sets; `controller.ts`/`epub-lifecycle.ts` own native pagination, lifetime and presentation. `runtime.ts` owns account cancellation and bridge orchestration; `sync.ts` owns replay, not source workers. Retired eager `zip.ts`/`archive.worker.ts` and unused main-buffer `identity.ts` disappear, not compatibility shims. `archive.ts` materializes only optional <=2 MiB responses.

## Exact integration / diagnostic seams

Public `index.ts` provider/hook/ReaderScreen/bridge and generated HTTP DTOs are unchanged. No API shape change or second queue exists.

- Reading DB remains `antholume-reading-v1`, now **Dexie version 2** (native IDB version 20), additive stores `sources` and `sourceChunks`. Existing events, receipts, access, leases, conflicts/history and checkpoints are **not reset**. Legacy available Blob books can be revalidated into the new source form; original bytes/position identity stay intact.
- `books` is the small projection row: `availability`, `sourceId`, `size`, `checksum` (full SHA-256), `protocolHash`, checkpoint/ref/title/author/cover. `bytes` is null for new books, **not an availability signal**. Frontend tests must assert public availability or follow `sourceId`, not require `books.bytes`.
- `sources[id]`: `{id,key,size,received,blob,complete,until,manifest,manifestHash}`. Local `blob` is the complete durable original Blob. Download `blob` is null; `sourceChunks` keys are `${sourceId}:${chunkNumber}`, index `sourceId`, value `{key,sourceId,data:ArrayBuffer}`. Every complete chunk is 262144 bytes, last shorter. Reserved/partial chunks cannot publish; `complete` and book pointer commit together. Expired stages/retry failures remove only their chunks/source; expiration is rechecked inside deletion. Active leases heartbeat; local Blob staging aborts its native transaction. Committed sources/events are preserved.
- `manifest.integrity`: `{sha256,protocolHash,digests[]}`; digests are full-source fixed chunk SHA-256. `manifest.index.entries` has original name/offset/data/size/expanded/method/flags/CRC and per-entry digest. Manifest also contains original OPF/spine/roles, compact document IDs/word counts, dependency graphs and image dimensions. `manifestHash` checks serialized validation metadata for local corruption; missing hashes fail rather than self-attest on open. These hashes are not document IDs.
- Repository internal `open(ref)` returns `{row,source,manifest}`, **not `bytes`**. Controller internal `open(source,saved?,signal?,manifest?)` uses that committed manifest without whole-book validation; a raw Blob input is validation/import, not the normal stored-open seam. Raw ArrayBuffer inputs remain only small public/test callers; production runtime supplies File/Blob/source descriptors.
- Worker handshake is **protocol 1 / browser schema 2 / event schema 1**. Root `/sw.js` identity and one-time retirement marker remain unchanged. Old unsupported tuples pause, never clear queues. Build emits hashed **`source.worker-*` and `staging.worker-*`** instead of the retired eager `archive.worker-*`; frontend precache injection already collects emitted chunks.
- Safe numeric diagnostics: ReaderScreen region has `data-reader-state` and `data-reader-metrics` JSON; controller `diagnostics()` returns source read/expanded/peak-entry counters, current/peak DOM and asset caches, loaded engine sections and content-document counts. `sourceStats`, `sourceScheduler` and `stagingWorkers` are internal test/qualification exports, not new public app state. Dedicated source workers expose `globalThis.__ANTHOLUME_SOURCE_METRICS__` for CDP inspection. No source text/path/account/token appears in these diagnostics.

The independent qualifier can adapt `verify-stored` by following `books.sourceId`: range-read `sources.blob.slice()` or sequential `sourceChunks.data` in <=256 KiB pieces. It must not concatenate them to verify originals or count its deliberate sequential verification as opening IO. Rebuild/capture current normal production assets before its isolated runs; do not use the old eager build.

## Memory, CPU and disk limits

- Original disk capacity **512 MiB**; total validated expanded capacity **2 GiB**; max 16,384 entries and 8 MiB central directory. These are disk/validation capacities, not retained-JS budgets.
- Original reads <=**256 KiB**. Network BYOB reads request <=64 KiB; generic fallback transport buffer <=2 MiB, otherwise explicit failure. At most two staging writers, each rotates at **8 MiB**; source hash/index/inflate concurrency <=2, queue <=16. Runtime admits at most two original operations. Network idle timeout 30s; whole original operation deadline 20min; explicit conflict-detail refresh retains a separate 3s abort budget.
- Per expanded binary resource **32 MiB**, XML/SVG **4 MiB**, CSS **512 KiB**, ratio **200**; actual output and CRC checked, not only declarations. Index/entry workers hard-terminate at **10s**, full incremental source-hash worker at **90s**, abort terminates current work. There is no unbounded parser/whole-source second ZIP parse.
- Canonical DOM LRU <=**2 / 8 MiB source XML**; document <=50k elements, depth 64; CSS <=50k AST nodes. Metadata <=16 MiB UTF-8 serialized, document identity metadata <=8 MiB; incremental dependency accounting stops at 8 MiB/131,072 edges before all-book accumulation.
- Static/visible resource working set <=**32 MiB**, outgoing/current leased URL cache <=**64 MiB**. Raster header limits stay <=8192 dimension and <=8,388,608 pixels/image; visible page <=33,554,432 pixels. Optional covers retain 2 MiB input and raster header/pixel gates. Native SVG/CSS/font/image allocations and browser/GPU cache eviction are **not an RSS ceiling**. No book-wide aggregate pixel rejection remains.

## Source-tree, compatibility and presentation

The existing EPUB.js **`blobUrl` XHTML transport** is now pinned explicitly: `application/xhtml+xml` in the same scriptless sandboxed iframe, **not a new engine/origin/topology**. XML serialization plus inert full-document XML round-trip preserves original namespaces/tree/text/IDs, including bodies that an HTML parser would repair. An independent inert HTML-head check and authored/generated XHTML style rawtext guard remain; active elements/attributes/URLs, malformed XML, NAV/NCX external/missing targets, font/SVG role aliases and archive escapes still reject before publication/live parsing. Original stored bytes are untouched. The old assertion that a valid XML body must also survive HTML body repair is retired; the former public tree-repair case is now a positive unchanged-XML-body test.

Localized ordinary-format support discovered through the authorized copies: canonical font role for legacy OpenType MIME with actual TTF/OTF signature checks; passive `samp`, SVG `version`, `default-style` and bounded `@page` declarations; exactly native-ignored `padding:auto` / misspelled `dispaly` are retained, not corrected into different layout. Body HTTP(S)/mailto references are rendered as inert absent fragments (no native outbound/context-menu fetch), preserving source bytes/tree/text/IDs. NAV/NCX targets and all fetching resources remain strict archive references. These are explicit passive compatibility cases, not a blanket CSS/resource-policy waiver.

F5: reflow keeps logical KO/CFI/fraction but retains newly observed page/pages; no event publication. F6: page controls >=44px inline/block at 320px and landscape, with pointer hit-testing. Iframe edge coordinates account for the real clipped parent viewport, not the full multi-column chapter width.

Pinned EPUB.js 0.3.93 error delivery also rejects otherwise-unsettled NAV/`displayerror` deferreds; owned lifetime abort cancels workers even without an external signal, and teardown stops its pending paint queue. Explicit same-original re-download repairs corrupt source/metadata without replacing checkpoints/events; valid originals can be reused only after bounded integrity verification. Publication never lowers a newer reading revision.

R1: frozen stable interval/event ID, durable exact credit retry and consumption before later navigation/checkpoint failure remain. R2: durable needs-refresh conflicts, shared bounded detail budget, delivery-before-detail fairness, late-response/decision fences and later explicit recovery remain. R4: method-specific legal DEFLATE option bits, strict STORE/encryption/ZIP64/local/CRC gates remain.
