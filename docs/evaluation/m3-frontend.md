## Architecture

Entry state: SSR and the old root worker existed; no production React application existed. Delivered state: compact Folio at `/app`, surviving SSR destinations as ordinary links, and build output for replacement at the existing root worker/manifest identity. Prototype demo state, fake reader and fixture API are not production dependencies.

Boundaries: React Router Data Mode, disposable TanStack Query server projections, in-memory validated session/CSRF coordinator, and the exact reader-owned provider/bridge seam. Only reader owns durable books/checkpoints/events/receipts/leases/conflicts/update registration. Frontend cancels and clears server queries before identity transitions; epoch/account checks protect bridge responses. Local IDs and account/origin/document composite identities never merge by content/title.

Library combines authorized reader projection and incrementally loaded real server pages in an identity map; local/stored records occur once, not once per fetched page. Counts distinguish visible loaded records from server total. Source/availability/search/dialogs are URL-backed. Description stays text. Unported uploads/metadata/history/Insights/settings/admin are explicitly ordinary SSR links, not simulated actions.

## Implementation invariants

- Real reader `index.ts` exports and backend-generated schema are consumed directly. Generated paths include `/api/v1`; no handwritten schema edits, fake HTTP bootstrap, mock production actions or duplicate reader queue exist.
- Session/access changes cancel and clear account-derived queries before publication. Account/epoch checks fence bridge requests/responses. An explicit sign-out intent (no identity/token) is persisted before offline logout; it prevents automatic cookie-based account restoration until invalidation and explicit sign-in. Reader receives immediate `logout` access and owns durable access/lease fencing. Denied storage disables automatic account access.
- Session/capabilities/pages/documents/state/devices/Problems are runtime-validated closed objects. Event methods preserve status and untrusted body for reader validation and have **no session-expiry side effect**. Only the reader's validated authentication Problem plus current durable lease may invoke `onSessionExpired`. Read/registration/binary expiry remains a separate current-account/epoch and validated `401 unauthenticated` Problem contract; malformed/redirected binary replies do not expire authentication. `openapi-fetch` consumes HTTP error bodies even with `parseAs: 'stream'`; the adapter must consume its untrusted `error` result, not read `response.json()` twice. Actual conflict tests exposed and now protect this boundary.
- Build emits `assets/app/index.html`, hashed JS/CSS/fonts/source-worker/staging-worker/lazy route chunks, compiled worker and preserved manifest. Precache hashes cover every emitted shell dependency. Build identity additionally hashes compiled worker code before injection, avoiding self-hash cycles and active-cache reuse on worker-only changes. Provider alone registers/coordinates updates.
- Vite uses loopback and exact browser public Origin. Worker shell fetches and compiled hashes proxy to Go rather than accidentally precaching HMR HTML. The retirement shell normalizes its location before constructing the data router. SSR/assets/root worker/manifest are proxied without Origin rewriting.
