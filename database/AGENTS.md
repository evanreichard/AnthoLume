# Database contracts

- The React upgrade supports the preceding pre-React production schema (Goose `20240510123707`), not databases from intermediate React builds. Base upgrade fixtures on that schema. Fresh initialization and restore use the same forward migrations. `schema.sql` is the bootstrap schema; the scoped-device migration owns `(user_id, id)` and its composite foreign keys. Preserve historical rows and known orphan metadata.
- Documents store a root ID and a canonical slash-separated relative path. Normalize redundant legacy `.` components at startup migration and restore; reject traversal and colliding archive entries. Treat legacy absolute paths only as remap hints; never activate mount paths from a backup. Library is the only managed root; initialize its default without overwriting configured paths. Other roots are import sources. Only Library files may be bundled or restored.
- Resume state belongs to `reading_heads`; timestamp-sorted per-device rows are history/compatibility effects, not a second current-state selector. Credit history is not rewritten by projections.
- Refresh `document_user_statistics` for document metrics and OPDS last-read ordering. OPDS sorts by the viewer's last read, then document creation, and skips fileless entries after pagination. Preserve the unused `user_streaks` schema and account-deletion purge for restored backups; streaks are computed from activity, not this table.
- Use file-backed SQLite for cancellation, lifecycle, reopen and durability tests. Canceling a modernc query can recycle its connection; `:memory:` then loses the schema, even with one open connection configured.
- Keep the write capability gate and refuse Down migration: old writers cannot safely update retained receipts and heads.
