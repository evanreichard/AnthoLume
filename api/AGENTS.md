# API boundary

- `openapi.yaml` defines `/api/v1`. Keep KOSync wire compatibility in the separate adapter: opaque positions, numeric accepted timestamps, and account-scoped aliases. From the repo root, run `make generate` and `make check_generation` with locked web dependencies. Generate Go/TS rather than editing them; TypeScript binary types require the Blob transform.
- Strict Gin supplies a pooled `*gin.Context`: unwrap `Request.Context()` before database/reading operations. Keep fallback disabled. Apply byte/media/UTF-8/duplicate-key checks before the validator and retain its validated body for strict binding.
- Route on escaped paths, decode opaque IDs once with `PathUnescape` (not query decoding), and decode validator path parameters before character-length checks. Preserve slash/plus/percent and 128-character Unicode IDs.
- `format: uuid` alone is not runtime validation in the selected validator. Keep the explicit event-ID pattern and string Go type so validation does not rewrite identity text.
- The JSON web API and external protocol adapters share identity/reading operations, never handlers. Preserve KO/OPDS wire contracts. Serve the React shell only for known navigation paths. Keep the Go allowlist and Vite navigation in sync.
- Metadata cover previews use numeric Open Library IDs and bounded JPEG responses; redirect targets stay on the Open Library / Internet Archive host allowlist. Keep remote cover selection in the editor draft until save.
- All cover routes (including OPDS and its fallback) apply `setCoverResponseHeaders`; serving bytes as an image does not make top-level SVG inert. Preserve bytes/MIME and allow image display, not script execution, document embedding or external resources. Check headers on both routes in Go and run `npm --prefix web run test:browser -- library-covers.spec.ts` for the real-browser regression.
- Apply shared Retry-After policy to 429/503 in every error renderer and direct legacy credential rejection; do not collapse credential work overload into a registration 400. Use `ClientIP()` for credential admission; forwarded addresses are trusted only through `TRUSTED_PROXIES`.
- Admin mutations recheck the acting administrator and session token in the write transaction. Only explicit backup downloads create database snapshots; deleting users and restoring backups do not. Native maintenance jobs persist bounded status history, coalesce active work by kind, and run with server-owned deadlines rather than request contexts. Stop job admission and drain canceled jobs before closing SQLite; reconcile leftover running jobs at startup on the single owning instance. React owns Administration; admin mutations are versioned API calls. Backups use a separate WAL reader; full backups serialize with library-file mutations, not reading or sync. Export and restore staging share catalog path validation, including deleted books; validate the exported snapshot, not the live catalog. Admin repair changes only the invalid reference without deleting files or history. Writer and restore share archive limits; publish only verified backups atomically. Full backups use bounded paths for restored or over-limit files and rewrite only the archived database copy so paths stay bounded across round trips. Only restore takes the exclusive request gate. Validate schema and install files at new paths before swapping the database. Rotate the reading generation inside the staged copy so old session cookies and event submissions fail as soon as restore commits.
- Web and KO uploads and imports share `attachCatalogFile`: attach to live fileless placeholders, preserve edited metadata and reading history, and leave existing placements to explicit relink. Stage and validate web uploads before taking the Library write lock; serialize only placement with Library switches. Bound network body reads before the restore gate can be held indefinitely. Download handlers resolve the book and root in one read transaction and release it before streaming the open file.
- Versioned errors are safe Problems. Logs must not contain request bodies, cookies, passwords or CSRF tokens, including panic recovery.
