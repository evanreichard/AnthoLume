# Browser EPUB reader

## Open and render

- When online, `runtime.ts` revalidates the file and fetches reading state. A passwordless offline profile can read cached copies within its origin and restore generation. Overlay only that profile’s checkpoints; never borrow position or drafts from a book’s original downloader. Read device metadata from `downloads` (library generation + document), private checkpoints from `positions` (account + document), and EPUB versions from `sources`. Point opens use those keys, never a shelf scan. Subscribe to the active shelf with Dexie; publish runtime-only changes from the last emitted view without rereading storage. A replacement switches the download pointer atomically; leases keep the old source readable. Saving exempts a copy from automatic eviction; removing clears all copies of the document in that library generation without touching any profile’s reading records. `/sw.js` caches only the public shell and build assets; IndexedDB owns device downloads, local-only books and the account-scoped outbox. Explicit offline review compares progress against the displayed revision and activity against the same account-local dates. Sign-out retains offline profiles; forgetting discards unsubmitted drafts.
- Stream originals into staging; use bounded chunk/range reads rather than buffering the whole book. Pinning checks the remembered IndexedDB profile in the same transaction as the pin. It publishes validated bytes and shared catalog data without fetching private state or acquiring a reader lease. A complete cached source is not proof that every chapter is safe. Explicit cache clearing includes quarantined server originals; preserve local books, checkpoints, outbox events and active leases.
- Give EPUB.js validated documents, not the original archive or network access. `source.worker.ts` checks ZIP entries; `content-policy.ts` and `chapter-policy.ts` validate resources before rendering. Preserve the scriptless frame, CSP and authored XHTML tree. Keep EPUB.js-specific lifecycle workarounds in `epub-lifecycle.ts`; release unused resources on failure as well as success.
- `codec.ts` translates KOReader positions. New positions must round-trip to the authored element; legacy fallback is for reading historical positions, not rewriting them. Offer opening from the beginning only when the saved position cannot be resolved; opening either way, reflow and choosing a resume candidate do not publish progress. Explain a missing or evicted download separately from a corrupt copy or an inaccessible book.

## Save and replay

- Bind the save policy to the open reader. Account opens atomically save a checkpoint, earned activity and authorized outbox work even during outages. Device opens save only private drafts. Neither reachability, review nor reconnect changes an open reader's policy or position. A fresh authenticated open resumes account progress, not an unapproved draft.
- Replay only for the authenticated account and restore generation. Retry immutable event IDs and payloads; authorized follow-on progress waits for the predecessor's receipt revision.
- Replay activity before progress. On revision conflict, fetch valid server state before removing pending progress; retain the device position as a resume choice. Distinguish terminal rejection from a retryable failure. Ignore stale responses after account or access changes.
- In browser tests, wait for the operation under test: settle prior appearance changes before observing resize, and have a worker signal that it is busy before advancing the parent clock to test its deadline.
- From the repo root, `npm --prefix web run test:reader` prepares fixtures and runs the reader browser suite. Use the app browser suite under `web/tests/` for behavior crossing the real Go API, including restore, sync and worker retirement.
