# Reading boundary

- `index.ts` exposes shell APIs without importing the EPUB renderer. `ReaderScreen.tsx` is the separate public entry for the lazy reader route. API DTO imports are type-only. Bridge owns credentials, repository owns checkpoints and the pending outbox, root SW owns shell/control only. Staging workers may write only `sources`/`sourceChunks`; no second queue.
- KOSync is an external opaque HTTP protocol; XPointer restoration is a separate KOReader/CRengine contract. Preserve server IDs, history and wire shapes. Match upstream partial-MD5 offsets including short reads; keep full-original SHA-256 separate. Generate every new path from direct same-namespace siblings, retaining authored anchors; require exact primary source/CFI round trips. Incoming historical strings remain byte-exact with child-first/legacy fallback reading; never bulk rewrite history or auto-start after unsupported restoration.
- Original EPUBs use disk-backed Blob ranges/256 KiB IDB chunks, never whole-book buffers/maps. WebKit fetch can coalesce large chunks: slice them before transferring to staging, and distinguish source-worker idle from absolute deadlines. Reuse Blob BYOB backing; hash chunks without another source copy. Entry output has one bounded allocation. Native raw-DEFLATE feeds are 256 bytes with concurrent consumption; target-browser raw-decoder support needs qualification. Retire consumed IDB/index/native buffers through acknowledged ownership transfer into <=8 MiB workers; terminate on rotation/completion/abort. Serial small reads/writes alone retained book-sized unforced backing storage.
- Publish online cached source, checksummed index metadata, and checkpoint atomically after bounded ZIP directory, package, and navigation validation. Online opening does not fingerprint the whole EPUB; full installs still retain the original SHA-256, per-chunk digests, and partial-MD5 fingerprint. Check local headers against the directory and enforce entry boundaries and CRC before returning bytes; only full/offline validation scans all local headers up front. Validate each chapter and its dependency closure before serializing or creating live asset URLs. The persisted cache is not proof of whole-book content validation. `books.bytes` is null for new books: availability follows `sourceId` + complete source, not Blob presence. Never mint a missing manifest integrity hash on open. Normal reopen checks metadata and every entry it uses, not the whole book; explicit same-original repair can revalidate and retains immutable events/checkpoints.
- Keep output/CRC/ratio/native raster and incremental metadata/edge limits. Canonical LRU is two, but separately unload nonlive engine sections/listeners/owners on EVERY settled command, including failure. Preserve the current display/checkpoint; roll back changed failed displays without guessed publication. Raster leases follow the clipped parent viewport. Inert owned intrinsic placeholders preserve authored one-axis/percentage geometry: never inject missing width/height attributes. READY requires actual decoded visible book assets, not placeholder natural dimensions. Bound native image/font/layout stabilization and verify the requested source element is clipped-visible before open/reflow/TOC readiness. Release offscreen actual URLs while retaining equivalent intrinsic geometry.
- EPUB.js consumes validated OPF/documents, never original ZIP bytes. Pin native `blobUrl` XHTML transport and XMLSerializer; preserve body namespaces/tree/text/IDs. Accept passive XHTML without a tag allowlist; retain active-content rejection, separate SVG validation, inert HTML head and style rawtext guards, early CSP, strict fetching/NAV/NCX roles and no-scripts sandbox. Own chapter head preparation rather than letting EPUB.js insert base and canonical URLs outside the archive policy. Drop unsupported CSS declarations without dropping adjacent styling; keep resource validation independent of declaration support. Persist only fixed-reason drop counts in the local manifest and log one browser-console summary per open; keep Vite console forwarding off. Reader font styles use XHTML namespace and WeakMap ownership, not a book-controllable element ID. WebKit suppresses parent-installed callbacks inside scriptless chapter frames; use the capability-tested parent gesture layer and explicit selection mode, not `allow-scripts`.
- Safari 26 derives browser chrome tint from viewport edges, not just `theme-color`. Keep the reader’s opaque fixed edge strips, `theme-color`, and `html`/`body` backgrounds in sync; restore app colors on exit.
- Pinned 0.3.93 seams own unload/orientation/URL cleanup, queue stop before destroy, rejection of unresolved NAV/`displayerror` deferreds and incorrectly typed `getContents` array. Reflow retains logical anchor but refreshes derived page metrics and never publishes. Jump history is session-only: push exact anchors after successful Contents or in-book jumps, and pop after a successful Back; page turns never add entries. Visible-word activity uses the legacy combined-CFI range, not two collapsed ranges (image endpoints can return null).
- Startup selects access before asynchronous cleanup and fences queued access application by generation. An open waits for its selected access generation to be applied and never proceeds across an account change. The reader owns open errors; cancelled opens are silent and must not surface in the Library. Provider projection and the native frame/progress are immediately masked on account/key changes.
- Commit checkpoints with either a sealed progress event or a latest draft in one transaction. Promote the draft only after a valid receipt, using that receipt’s revision; do not rebase against an unrelated server head. A forward activity candidate has one stable interval/event ID and frozen payload. Committed credit consumes its interval before later engine/checkpoint publication; exact retries are durable no-ops, collisions reject, failed credit commits do not consume it. Add no idle/reread heuristics.
- Replay sends activity before progress. Tabs can retry the same immutable event; the server deduplicates by event ID. Delete acknowledged events and promote progress drafts atomically. On a revision conflict, adopt validated server state and keep one device resume candidate on the book, without keeping a sendable event. If server state is unavailable, retain pending progress for retry. On open, choosing either position must not publish progress; clear the candidate only after a successful open. Account epochs and aborts fence stale responses.
- ZIP flags are method-specific: DEFLATE permits option bits 1/2 plus descriptor/UTF-8; STORE permits only descriptor/UTF-8. Encryption/reserved bits, ZIP64, local/central mismatch, actual limits and CRC remain fail-closed.
- Online opens revalidate the exact-account EPUB against the server; use bounded cache eviction without deleting checkpoints/events or active sources. The root retirement worker deletes only React shell caches and unregisters. Worker modules use structural host types, not a conflicting WebWorker global lib reference.
- Tests: from `web`, run `node node_modules/vitest/vitest.mjs run src/reading/tests/unit`. Reader Playwright uses `src/reading/tests/playwright.config.ts` (5346); worker retirement uses the actual-Go `web/tests/worker.spec.ts`. Set `CHROMIUM_PATH` when needed. Before the reader browser suite, run `node src/reading/tests/generate-fixtures.mjs` to recreate the uncommitted `large-media.epub`. Configs generate the missing public 300 MB fixture into scratch without whole-file buffering.
