# React application

- Import shell-facing reader APIs through `src/reading/index.ts`. Load `ReaderScreen` only from the lazy reader route. The Go shell allowlist (`api/app-shell.go`), Vite navigation and React routes must agree on direct links and reloads.
- Build book links with `bookPath` and read the ID from the query string: React Router path parameters collapse literal `%2F` and `/`. Bind the resulting book reference to the authenticated account. Retirement links carry only a document intent through login, never an account to trust.
- `src/session.ts` owns session transitions; `src/api/client.ts` binds requests to the initiating identity. Scope server reader state by origin, immutable account ID and restore generation, not username. Clear old query data on identity changes; preserve the reader during same-account refreshes. Validate an error response before treating it as session expiry; `openapi-fetch` supplies the already-consumed error body as `error`.
- Use `PageHeader`, `Dialog`, `Controls` and `Skeleton` for shared UI. Keep loaded content visible on refresh and restore focus after dialogs. Check changed layouts at 320px, 390 × 844 and desktop; controls must be clickable, not merely visible.
- From the repo root: `npm --prefix web run build` typechecks and builds; `npm --prefix web test` runs unit tests. After building, `npm --prefix web run test:smoke` runs the PR browser checks. For browser changes run the affected specs too (`npm --prefix web run test:browser -- <spec>`); dispatch CI manually for the full app, reader and race suites before the next monthly or tagged run. Use `tests/fixtures.ts` for an isolated Go server, database and files; inject faults in the fixture, not production endpoints. Reader-specific guidance is in `src/reading/AGENTS.md`.
