# Production frontend

- `src/reading/**` is reader-owned; `src/api/schema.gen.ts` is backend-generated. Consume only the reader's `index.ts` handoff. Frontend alone owns package/lock files.
- Use `PageHeader` from `src/ui.tsx` for app route header rows, including back/action-only rows above a `BookHero`. Every page uses the common route shell and shared header unless the user explicitly approves an exception. Only basic authentication screens (sign-in and registration) and the full-screen reader are exempt. Anonymous pages such as local-book export still use the shell; authentication guards are independent of layout. Library, Insights, and Book Detail use the shared shell width and gutters; constrain individual elements when needed, not the entire page. Use 390 × 844 CSS pixels for standard mobile previews, check 320px for narrow-screen regressions, and inspect desktop screenshots in the relevant themes and states. Reuse `src/Controls.tsx` for shared interaction and layout: cards and headers, route tabs, pagers, pill selects, radio choices, disclosures, and action rows. Shared controls own markup, styling, and accessibility; callers own navigation destinations, state, and fetching. Use `Button`, `ButtonLink`, `JoinedActions`, and `Dropdown` with `size="slim"` inside cards (32px visual, 44px target); use the default full size for page actions and navigation. Put longer explanations in details or confirmation, not default card copy.
- Use `Dialog` from `src/ui.tsx` for app modals. Set `size="wide"` for wider forms, `layout="scroll-body"` for fixed-height browsers, and use the `toolbar` and `footer` slots for controls that stay visible while the body scrolls.
- Use `src/Skeleton.tsx` for initial content loads: mirror the loaded layout, announce loading once, and honor reduced motion. Keep content visible during background refreshes; keep feedback for explicit actions inline.
- Cancel and clear query data on real identity transitions. Background session checks preserve the current reader access object on same-account responses and transient failures. Bind account-scoped requests to the initiating account UUID and restore generation; on mismatch fence the old view and recheck the session without replaying writes. Scope reader caches, checkpoints, and outboxes to the server-issued account UUID and origin; usernames are for login and display only. Never adopt username-keyed records. Keep credentials and CSRF out of browser persistence.
- `openapi-fetch` consumes error bodies even with `parseAs: 'stream'`: validate/forward the untrusted result `error`, not `response.json()` twice. Event delivery never expires sessions; only the reader's validated Problem + current durable lease may call `onSessionExpired`. A stale lease need not change the frontend account epoch. Read/binary 401 handling requires current-account checks and a validated authentication Problem.
- Browser acceptance uses `tests/server` with actual production Go router/database and HTTP credentials, synthetic files/DB, `-mod=readonly`, and owned loopback ports. Build the router once per worker; give each test its own Go process, SQLite database, and files. Use the worker binary fixture for custom launches and the authenticated session’s reading generation for seed event writes. Restarts within a test keep its fixture directory; file-controlled faults never add production endpoints.
- Retirement URLs carry only a bounded opaque document ID through login. Construct the BookRef from the authenticated exact-origin account; wait for the reader's public ready/resume-account projection before immediate cached-book opening. Hide prior expired-account projections while intent awaits authentication. Worker retirement is best-effort and never gates reading or saving.
- Keep one recovery presenter/provider coordinator. Reader recovery is a bounded compact dock with native-dialog details; reserve its measured height in the frontend reader viewport so it cannot cover reader panels/footer. Test Appearance/Contents/footer and recovery center hit-testing plus unforced clicks at 320/390/landscape, not only visibility.
- Library sort is URL-owned and applied by the shared list before pagination; Library Add book uploads to the server; previously imported local books are export-only. Named 44px Clear search clears draft plus applied `q`, preserves sort and focuses the input; native UA decoration stays hidden. Successful durable actions focus a surviving heading after projection/navigation; cancel restores only a connected opener.
- Large-book source/staging/hash/resource ownership stays in `reading`. Reader lifecycle cancels cache population through its AbortSignal; cache eviction never edits queued progress. `BookRow.bytes === null` is valid: check public availability, actual source/manifest/chunk backing and native reading, never a whole-blob shim.
- Keep `/sw.js` as a one-time retirement endpoint, not a newly registered offline worker. Retire only owned shell caches; preserve book data, queued events, and unrelated storage.
